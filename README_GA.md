# Алгоритм 3: генетическая расстановка вышек

Чистый Python + numpy, новых зависимостей нет. Обучать ничего не нужно.

## 1. Положить файлы в проект

Скопируйте файлы из этой папки в корень проекта `ZoneOneM` с той же структурой
(существующий `algorithms/auto_placement.py` заменяется — в нём заглушка Алгоритма 3
заменена на вызов ГА, Алгоритмы 1 и 2 не тронуты):

| Файл | Что это |
| --- | --- |
| `algorithms/ga_placement.py` | Генетический алгоритм: кандидаты, целевая функция, операторы, локальный поиск |
| `algorithms/auto_placement.py` | «Алгоритм 3 (генетический)» в списке алгоритмов программы |
| `tests/test_ga_placement.py` | 14 тестов |
| `tools/compare_ga.py` | Сравнение с Алгоритмами 1 и 2 для отчёта |

В программе: нарисуйте участок, выберите «Алгоритм 3 (генетический)» и нажмите «Запустить».
Поля из панели (макс. вышек, целевое покрытие, качество, шаг сетки и азимута,
секторов на площадку, мин. прирост) учитываются так же, как в Алгоритмах 1 и 2.

## 2. Как устроен

**Особь** — набор вышек. **Ген** — (точка-кандидат, азимут антенны). Высота берётся
так же, как в GUI: на крыше — высота здания + 5 м мачты, на земле — высота из типа вышки.

**Точки-кандидаты** (до 1500): крыши зданий внутри участка, площадки Алгоритма 1,
равномерная сетка «опор» на земле. Всё вне участка и в запретных зонах отброшено,
поэтому любая особь автоматически соблюдает запретные зоны.

**Целевая функция** (больше — лучше):

```
F = 1.0·покрытие + 0.05·запас_сигнала − 0.08·стоимость − 0.03·перекрытие
```

- покрытие — доля точек участка с уровнем не ниже выбранного качества (как в статистике программы);
  за достижение цели дается премия 0.1, а покрытие сверх цели считается с весом 0.25 —
  поэтому после цели выгоднее убрать вышку, чем добавить;
- запас сигнала — насколько уровень выше требуемого (0..1);
- стоимость — (площадки + 0.5 за каждый доп. сектор на той же площадке) / макс. вышек;
- перекрытие — доля точек, которые покрывают две вышки и больше.

Уровни сигнала каждой пары «кандидат × азимут» считаются один раз и кешируются,
поэтому оценка особи — это только поэлементный максимум нескольких массивов.

**Эволюция:**

| Параметр | Значение |
| --- | --- |
| Популяция | 60 |
| Отбор | турнир, k = 3 |
| Элитизм | 4 лучших переходят без изменений |
| Скрещивание (p = 0.8) | карта режется случайной прямой: с одной стороны вышки родителя A, с другой — B |
| Мутации (p = 0.2) | сдвиг вышки к кандидату в радиусе 150 м; поворот антенны на шаг; новая вышка у случайной непокрытой точки (антенна — в её сторону); удаление вышки с наименьшим вкладом |
| Ремонт | без повторов, не больше «секторов на площадку» и «макс. вышек» |
| Остановка | 200 поколений, или 20 поколений без улучшения, или 120 с |
| Финал | локальный поиск: убрать / сдвинуть к соседу / повернуть каждую вышку, пока F растёт |

**Начальная популяция:** результат Алгоритма 1 (затравка) + случайные особи
с разнесёнными вышками. Число вышек в случайной особи — около числа вышек затравки.
Если обучена модель Алгоритма 2, её карта выгодности задаёт веса выбора
кандидатов (сеть — только подсказка; без модели ГА работает так же).

В ответе вышки идут в порядке вклада (как ставил бы жадный алгоритм); вышки,
дающие меньше «мин. прироста» точек, отбрасываются.

Настройки меняются через `GAParams` в `ga_placement.py`
(например, `seed_algorithm_2=True` — добавить затравку Алгоритма 2,
`seed=1` — воспроизводимый результат).

## 4. Что показал прогон

`python tools/compare_ga.py --scenes 12` (те же случайные участки, что у `compare_ai.py`,
4-ядерный Linux-сервер; «ГА» — без затравки, «ГА+А1» — с затравкой Алгоритма 1, как в программе):

| | Алг. 1 | Алг. 2 (ИИ) | ГА | ГА+А1 |
| --- | --- | --- | --- | --- |
| Среднее покрытие | 97,0% | 96,1% | 96,6% | **97,2%** |
| Вышек всего (12 участков) | 38 | 37 | 36 | **35** |
| Среднее время, с | **1,0** | 2,0 | 7,0 | 6,0 |

- На 6 простых участках из 12 (1–2 вышки) все алгоритмы дают одно и то же.
- Там, где вышек не хватает (макс. 3 вышки, цель недостижима), ГА+А1 поднял покрытие
  с 84,6% до 87,1%; на другом участке — с 96,2% до 98,0% тем же числом вышек.
- Где цель 95% достижима, ГА достигает её меньшим числом вышек: 5 вместо 7 (95,4%
  против 98,3%) и 3 вместо 4 (96,5% против 96,4%). Это следствие целевой функции:
  покрытие сверх цели почти не ценится, а каждая вышка стоит денег.
- Без затравки ГА в среднем чуть хуже Алгоритма 1 (96,6% против 97,0%), но на одном
  участке нашёл 98,8% против 96,4% тем же числом вышек.
- Цена — время: ГА в 6–7 раз медленнее Алгоритма 1 (до 30 с на крупном участке
  с секторными антеннами), почти всё время уходит на расчёт новых вышек-кандидатов.
